== Prerequisites

* Apptainer (or Singularity 3.8+) on the host.
* RepeatMasker `Libraries/` directory available on the host (license-encumbered; not shipped). Path goes to `make sifs`.
* GeneMark-ES license + tarball (`gmes_linux_64_*.tar.gz`) on the host. Path goes to `genemark.gm_home:` in the config.
* `pixi` for the host CLI (https://pixi.sh).
* Slurm if dispatching per-rule jobs (optional; single-host runs are fine).

== Inputs

| Required | Optional |
|---|---|
| Genome FASTA | RNA-seq BAM (or STAR / gsnap inputs) |
| Repeat-modeller species library | Trinity-GG transcripts |
| SwissProt protein FASTA (BLAST DB) | Manual curations GFF |

The config schema is at `workflow/config/config.schema.yaml`. An example
that runs against the bundled 1 Mb fixture is at
`test_suite/mini-config.yaml`.

== One-liner

[source,bash]
----
make sifs
cp test_suite/mini-config.yaml my-genome.yaml
$EDITOR my-genome.yaml
bin/jamg run --config my-genome.yaml --cores 20
----

The CLI wraps Snakemake; `--cores`, `--profile`, `--dry-run`, `--unlock`,
`--rerun-triggers`, etc. all pass through.

== Pipeline stages

[cols="1,3"]
|===
| Stage | What

| repeats
| 4-pass RepeatMasker (species + rna-specific + general + contamination
  check) + merge → softmasked + hardmasked genome FASTAs + repeats GFF.

| rnaseq
| 3 input modes (`bam` | `star` | `gsnap`) → sorted-indexed BAM +
  augustus hint GFF.

| tgg
| Trinity genome-guided assembly → `Trinity-GG.fasta` (consumed by PASA).

| pasa
| `setup_db` → `align` → `compare_transdecoder` → `hints`. Produces
  pasa.transdecoder.{genome,gff,pep,cds}.gff3 + pasa_assemblies.gff3 +
  polyAsites hints.

| proteins
| BLASTX vs SwissProt → swissprot.blastx.gff3 + hints.

| genemark
| `gmes_petap` (ET if RNA-seq junctions, otherwise ES) → genemark.gff3.

| golden
| `bin/prepare_golden_genes.pl` builds the high-confidence golden gene
  set from PASA + GMAP + exonerate. Pure-Perl canonical-splice +
  CDS-completeness validator in `Golden::Filter`. Outputs the golden
  GFF + GenBank training files + augustus hints.

| augustus
| Hint pile (repeats + rnaseq + pasa + golden + proteins + polyA) →
  chunked Augustus run via `run_split_augustus.py` + ParaFly → merged
  `augustus_results.gff3`.

| evm
| Tag + sort the 4 ab-initio sources (augustus, genemark, golden,
  pasa-transdecoder); preflight against `evm_weights.txt`; symlink
  inputs into `evm/`; invoke EvidenceModeler → `EVM.gff3`.

| ogs
| Rescue Augustus-only genes via `bin/trim_overlap_gff3.py`; two
  post-EVM PASA compare-load passes; `create_features_from_gff3.pl`
  rewrites IDs; `fix_pasa_evm_gff.pl` + `gt gff3` validates and
  sorts; `gffread` emits the six final OGS products.
|===

== Outputs

Under `outdir:` from the config:

* `OGS.gff3` — Official Gene Set.
* `OGS.{mRNA,CDS,pep}.fasta`.
* `OGS.gtf`, `OGS.bed`.

Intermediate artefacts under `outdir/{repeats,rnaseq,tgg,pasa,
proteins,genemark,golden,augustus,evm,ogs}/`.

== Troubleshooting

[cols="1,3"]
|===
| Symptom | Resolution

| `RuleException`: `command not found: prepare_golden_genes.pl`
| Driver lives at `$REPO/bin/`, not in the SIF's `/opt/jamg/bin/`. The
  `golden.smk` rule prepends `$REPO/bin` to `$PATH`; verify the binding
  resolved (`apptainer exec containers/jamg.sif env | grep PATH` from
  the rule's shell).

| `LockException` on snakemake startup
| Previous run was killed mid-execution. `rm -rf .snakemake/locks/`.

| GeneMark key expired
| Re-download `gm_key_64` from http://exon.gatech.edu/GeneMark/license_download.cgi
  and replace the file under `gm_home`.

| `/dev/shm` fills up
| The PASA + post-EVM PASA compares use `/dev/shm` for their SQLite
  databases. If the node has multiple PASA workflows running, the
  shared shm fills. Restart, or temporarily redirect via
  `apptainer --bind /tmp:/dev/shm`.

| `Unknown GFF format for ##gff-version 3`
| GMAP emitted a header-only split file. Already mitigated in
  `Golden::Alignment::run_gmap`; if it recurs, check the gmap
  command-line flags and the `*.uniq` split files.

| EVM preflight fatals: `predictions GFF contains source tokens
  absent from EVM weights`
| Add an `ABINITIO_PREDICTION <token> <weight>` row to
  `workflow/config/evm_weights.example.txt` (or your overriding
  per-genome weights file), or drop the offending source from
  `evm.extra_gff[]`.
|===

== Re-running parts of the DAG

Use `--until <rulename>` for a partial DAG. For instance, to refresh
augustus without re-running EVM:

[source,bash]
----
bin/jamg run --config my-genome.yaml --until augustus --rerun-triggers mtime
----

Snakemake's `--rerun-triggers mtime` avoids re-running rules whose
inputs are unchanged in time even when the rule body or container
environment was edited.

== Test infrastructure

The test suite under `tests/` has two tiers, both deployability-focused
(do the rules wire up and produce structurally-valid output) rather than
biology-focused (does the prediction match a reference annotation).

=== Tier 1: per-rule smokes (`tests/rules/test_*.sh`)

Each `test_X.sh` exercises one rule end-to-end on the 100 kb fixture in
under 2 minutes (Trinity-GG, PASA and the full DAG each take longer).
The trick is pre-staging: each test script copies the relevant snapshot
subdirs from `test_suite/fixtures/snapshot/` into `test_suite/output/`
with mtime `2038-01-15`. Snakemake's `--rerun-triggers mtime` then
treats the staged outputs as up-to-date and runs only the target rule.

The snapshot itself is gitignored (binary, ~150 MB) and regenerated by:

[source,bash]
----
bash tools/regen_snapshot.sh
----

which:

1. Builds fixtures if missing (`tools/build_fixtures.sh`).
2. Pre-stages the committed genemark fixture
   (`test_suite/fixtures/genemark.gff3`, a 100 kb subset of a 1 Mb
   `gmes_petap --ET` prediction; genemark itself cannot run on
   100 kb so this is the canonical pre-stage).
3. Runs the seed DAG (`--until ogs_emit`).
4. Calls `tools/snapshot_dag_outputs.sh` to copy `output/` into
   `fixtures/snapshot/` with a sha256 manifest + PASA sqlite
   portability check.

Once the snapshot exists, any `tests/rules/test_X.sh` invocation
pre-stages everything upstream of X via `tools/stage_fixtures.sh` and
runs only X. The committed genemark fixture is staged separately
(it does not live in the snapshot tree).

=== Tier 2: end-to-end baseline (`tests/e2e/test_full_dag.sh`)

Intentionally does NOT pre-stage anything except the committed
genemark fixture (which is required because `gmes_petap` cannot
converge on the 100 kb extract). Every other rule runs from scratch.
This is the gold-standard correctness check; runtime is 15-30 min on
Layout A and ~5-10 min once Layout B (per-rule sbatch dispatch via
`workflow/profiles/slurm/`) lands.

=== Known limitation: EVM on the 100 kb fixture

`EVidenceModeler` (in `jamg.sif`) raises a fatal
`offset to augment prediction score for predicted introns is negative`
when fed many overlapping PASA isoforms in a small genome window. The
seed DAG therefore completes only as far as `augustus` on the 100 kb
fixture, producing a partial snapshot that supports every per-rule
smoke EXCEPT `test_ogs`. The blocker is in `EVidenceModeler`'s perl
(`evidence_modeler.pl:3507`), not in JAMg; fixing it requires patching
EVM upstream and rebuilding `containers/jamg.sif`.

=== Adding a new per-rule test

1. Create `tests/rules/test_<rule>.sh` modelled on `test_evm.sh`.
2. The script must (a) symlink-or-copy required fixtures from
   `test_suite/`, (b) call `bash tools/stage_fixtures.sh <upstream-subdirs>`,
   (c) run `pixi run bin/jamg run --until <rule>`,
   (d) assert on the rule's declared outputs.
3. Tests use the 100 kb default config (`test_suite/mini-config.yaml`)
   unless they need GeneMark training, in which case use
   `test_suite/mini-config-1mb.yaml` and `test_suite/output-1mb/`.

== Layout B: per-rule Slurm dispatch

Production runs and `tests/e2e/test_full_dag.sh` use the snakemake
`slurm` executor (Layout B) via the profile at
`workflow/profiles/slurm/`. The driver `bin/jamg` runs on the head
node (lazebnik); snakemake submits each rule as its own sbatch via
`snakemake-executor-plugin-slurm` (bundled in `containers/jamg.sif`),
so rules fan out across the 4-node cluster (`montessori`, `pilgrim`,
`roughgarden`, `themistoclea`).

[source,bash]
----
# Production: each rule's threads/mem_mb map to sbatch --cpus-per-task / --mem.
bin/jamg run --config my-genome.yaml --executor slurm --jobs 32

# End-to-end test (run FROM the head node, NOT wrapped in sbatch):
bash tests/e2e/test_full_dag.sh
----

Each rule's `threads:` and `resources: mem_mb=N` declarations drive
the sbatch flags. Total wall clock becomes the DAG critical-path
length, not the sum of all rule times. Per-rule smoke tests
(`tests/rules/test_*.sh`) stay on Layout A (single-process snakemake
on the head node) because they exercise only one rule each via the
pre-stage architecture and don't benefit from cluster parallelism.

The profile sets `slurm_partition=main`, `runtime=10080` (7 days;
partition default is INFINITE), `restart-times=0` (failures surface
immediately), and `rerun-incomplete=false` (trust snakemake's mtime
check). Override per-job via rule-level `resources: slurm_partition=de21`
etc. in `workflow/rules/*.smk` if a rule needs a different partition.
